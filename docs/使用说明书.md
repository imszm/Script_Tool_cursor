# ppx_testkit 使用说明书

这份说明只讲怎么看目录、怎么跑工位。源码逻辑没有改动。下面的「文件注释」写在本文里，打开对应文件时可以对照着看。

## 1. 先记住三件事

1. 现在的入口只有 `ppx-test`。`Tool/`、`L5_CCB&MCB白盒测试/`、`L5系列SMT&组装升级测试工具/`、`R3_*`、`P3系列*` 里的 `.py` 是旧脚本，留着对照，直接运行它们不会走新的配置和日志。
2. 一个工位 = 一份 `config/stations/<工位名>.yaml`。文件里的 `app:` 决定调用哪段 Python。改次数、串口、关键字、坐标，先改配置，不必改代码。
3. 串口号写在 `config/local.yaml`（这个文件不入库）。工位 yaml 里不写死 `COM` 口。

## 2. 第一次在 Windows 上跑

在项目根目录（能看到 `pyproject.toml` 和 `config/` 的那一层）打开终端。

```bat
scripts\setup_env.bat
```

这一步会：

- 用 Python 3.11 创建 `.venv`
- 安装本包和 Windows、界面、报告依赖
- 如果还没有 `config\local.yaml`，就从 `config\local.yaml.example` 复制一份

然后改 `config\local.yaml` 里的串口。示例口是旧脚本当时的口，本机不一定一样。先看机器上实际有哪些口：

```bat
.venv\Scripts\python.exe -m ppx_testkit ports
```

安装成功后也可以直接打 `ppx-test`，它和 `python -m ppx_testkit` 是同一个入口（定义在 `pyproject.toml` 的 `ppx-test = ppx_testkit.cli:main`）。

第一次接通硬件，把循环次数压到 2 轮：

```bat
scripts\run_station.bat relay_power_cycle --set test.cycles=2 --port relay=COM3 --port device=COM13
```

把 `COM3`、`COM13` 换成 `ports` 命令打出来的口。也可以把口写进 `local.yaml`，以后就不用每次加 `--port`。

跑之前可以先看合并后的配置，这一步不会打开串口：

```bat
ppx-test show relay_power_cycle
ppx-test list
```

不想记命令时，双击 `scripts\start_ui.bat`（或执行 `ppx-test ui`）。浏览器打开 `http://127.0.0.1:8765`，左边选工位，右边对串口，轮次留空就用配置里的默认值。停止和 Ctrl+C 一样会做收尾。这个页面不改关键字和坐标。

双击 `scripts\run_station.bat` 且不带参数时，窗口只列出工位，按键后关闭，不会开始测试。

## 3. 一条命令是怎么执行的

以 `ppx-test run relay_power_cycle --set test.cycles=2 --port relay=COM3` 为例。

```
ppx-test
  └─ src/ppx_testkit/__main__.py
       └─ cli.main()                         解析子命令 list / ports / show / run
            └─ load_settings("relay_power_cycle")
                 按第 4 节的顺序合并 YAML、环境变量、命令行
                 station_schema 校验类型和必填段
            └─ setup_logging()               建立 logs/<工位>/<时间>/
            └─ 把生效配置写成该目录下的 config.yaml
            └─ import ppx_testkit.apps.power_cycle.relay_power_on
                 模块名来自工位 yaml 的 app: power_cycle.relay_power_on
            └─ 调用 run(settings, ctx)
                 应用用 core.factory 打开串口、建继电器、建关键字监控
                 多数压测再交给 StressRunner 循环
            └─ shutdown_logging()            无论成败都会收尾
```

`app:` 的写法是包内相对路径，点号对应目录。`power_cycle.relay_power_on` 就是文件 `src/ppx_testkit/apps/power_cycle/relay_power_on.py`，里面必须有函数 `run(settings, ctx) -> int`。

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 通过 |
| 1 | 测试未通过，或应用内部未捕获的异常 |
| 2 | 配置错误（缺字段、类型不对、应用模块加载失败） |
| 3 | 硬件或通信故障（打开串口失败、继电器发送失败等） |
| 130 | Ctrl+C |

日志目录 `logs/<工位>/<YYYYmmdd_HHMMSS>/`：

| 文件 | 谁写入 | 内容 |
| --- | --- | --- |
| `full.log` | `logger.py` | 全程，含 DEBUG 和串口收发十六进制 |
| `error.log` | `logger.py` | WARNING 及以上 |
| `device_raw.log` | `logger.py` 的 `ppx.raw` | 设备原始串口文本，按大小轮转，不进控制台 |
| `config.yaml` | `cli.py` | 这次真正生效的配置 |
| `summary.json` | `StressRunner` 或具体应用 | 轮次、成败、是否保留上电 |
| `logs/console_<工位>_<时间>.log` | `run_station.bat` | 控制台原样副本 |

业务代码只调用 `get_logger(__name__)`，不要自己再加日志 handler。

## 4. 配置是怎么叠在一起的

后者覆盖前者：

1. 代码里 dataclass 的默认值
2. `config/default.yaml`（目前主要是日志目录和级别）
3. `config/stations/<工位>.yaml`，其中 `include:` 引入 `config/stations/_fragments/` 里的公共片段
4. `config/local.yaml`：顶层键对所有工位生效；`stations.<工位名>` 只对该工位生效
5. 环境变量 `PPX__A__B`，例如 `PPX__TEST__CYCLES=2` 相当于 `test.cycles: 2`
6. 命令行 `--set test.cycles=2`，以及 `--port relay=COM5`（等价于 `--set serial.relay.match.port=COM5`）

`--no-local` 会跳过第 4 步。

未知字段、缺必填项、类型不对，会在打开硬件之前失败，退出码 2。已注册的应用由 `src/ppx_testkit/station_schema.py` 规定必须有哪些段（`test`、`serial.relay`、`relay` 等）。

工位 yaml 里继电器的 `on` / `off` 必须加引号，例如 `"on": 0x50`。不加引号时 YAML 会把 `on` 当成布尔值。

## 5. 目录：哪些要看，哪些先不用管

```
pyproject.toml              包名、依赖、ppx-test 入口
config/default.yaml         全局默认（日志）
config/local.yaml.example   本机串口示例，复制成 local.yaml
config/stations/*.yaml      每个工位一份，这是改行为的第一处
config/stations/_fragments/ 多个工位共用的继电器口、关键字
src/ppx_testkit/cli.py      命令行
src/ppx_testkit/settings.py 读配置、合并、校验
src/ppx_testkit/logger.py   每次运行一个日志目录
src/ppx_testkit/station_schema.py  各应用允许的配置段
src/ppx_testkit/core/       串口、继电器、关键字、协议、循环、报告、窗口
src/ppx_testkit/apps/       各工位流程，只编排，不直接 import pyserial
resources/                  DLL、C 头文件、图片、用例表
scripts/setup_env.bat       装环境
scripts/run_station.bat     带控制台日志跑一个工位
tests/                      无硬件单测；带 hardware 标记的要实机
logs/                       运行后才出现，不入库
```

`core` 里和跑工位最相关的几块：

| 目录 | 作用 |
| --- | --- |
| `core/factory.py` | 按配置打开串口、建继电器、建关键字监控。应用从这里拿硬件对象 |
| `core/serial/` | 找口、打开、读写。异常变成 `PortNotFoundError`、`SerialTimeoutError`、`SerialDisconnectedError` |
| `core/relay/` | `command`（0x50/0x4F 或 ASCII）、`icse_a0`、舵机 |
| `core/monitor/` | 设备日志分行、成功/异常关键字、滑动窗口熔断 |
| `core/runner/` | `StressRunner`：循环、统计、Ctrl+C、结束时一定 teardown |
| `core/protocol/` | L5 用 v1，R3 用 v2。两套 `ppx_region.dll` 不同，分别在 `resources/dll/l5` 和 `resources/dll/r3` |
| `core/gui/` | 窗口点击、截图、结束进程。只有 PC 工具和 FCT 用到 |
| `core/report/` | CSV、HTML、Excel 用例 |

`apps` 按工位种类分目录，同一个应用可以被多份 yaml 复用。例如 `power_cycle.relay_power_on` 同时服务继电器开关机、NFC 开关机和把手开关，差别全在各自的 yaml。

旧目录先不要改，也不要作为入口：

| 目录 | 现在的角色 |
| --- | --- |
| `Tool/` | 开关机、充电、舵机、灯、计算器等旧脚本 |
| `L5_CCB&MCB白盒测试/` | L5 灯板 / 主控白盒旧脚本 |
| `L5系列SMT&组装升级测试工具/` | PC 工具、治具压力旧脚本 |
| `R3_MCB白盒测试/`、`R3电机专项测试/`、`R3系列总装测试工具/` | R3 白盒、刹车、总装旧脚本 |
| `P3系列SMT&组装升级测试工具/` | P3 FCT 旧脚本 |

## 7. 一份工位文件怎么读

打开 `config/stations/relay_power_cycle.yaml`，按这个顺序看：

| 字段 | 含义 |
| --- | --- |
| `include` | 先并入公共片段：CH340 继电器口、`0x50/0x4F` 指令、公共异常关键字 |
| `station` | 工位名，也是日志子目录名 |
| `app` | 要加载的 Python 模块 |
| `description` | `ppx-test list` 时显示的一行字 |
| `serial.relay` / `serial.device` | 两路串口。`match.port` 一般由 `local.yaml` 或 `--port` 补上；也可以按描述匹配 CH340、CP210 |
| `relay` | 继电器类型、通道字节、写完后等多久 |
| `keywords` | 成功关键字、异常关键字、频率熔断（几秒内出现几次就停） |
| `test` | 轮次、上电听多久、断电等多久、失败是否保持上电 |

`serial` 下面的名字（`relay`、`device`、`servo`、`lcb`、`mcb`）必须和该应用代码里 `open_serial(settings, "relay")` 用的名字一致。`ppx-test show <工位>` 能看到合并之后的完整结果，包括 `local.yaml` 是否生效。

## 8. 必要文件注释

对照这些文件即可，不必从旧脚本读起。

### `src/ppx_testkit/__main__.py`

`python -m ppx_testkit` 进这里，只做一件事：调用 `cli.main()` 并用它的返回值作为进程退出码。

### `src/ppx_testkit/cli.py`

四个子命令：

- `list`：扫描 `config/stations/*.yaml`，打印工位名和 `description`
- `ports`：列出本机串口设备名、描述、硬件 ID
- `show`：合并配置并打印，不打开硬件
- `run`：合并配置、建日志、按 `app` 动态导入、调用 `run(settings, ctx)`

`settings` 是只读配置对象。`ctx` 是这次运行的目录和写文件方法（`ctx.write_text`、`ctx.write_json`、`ctx.artifact`）。应用返回整数退出码；抛出 `ConfigError` 得到 2，抛出其他 `ToolError` 得到 3。

### `src/ppx_testkit/settings.py`

`load_settings(station)` 是读配置的唯一入口。`from_dict` 把 YAML 映射成冻结的 dataclass：多出来的字段、缺必填、类型不对都变成 `ConfigError`。`AppSettings.section("test", RelayPowerCycleConfig)` 是应用取自己那一段配置的方法。`AppSettings.raw("a.b")` 按点号路径取原始值。

### `src/ppx_testkit/station_schema.py`

`load_settings` 返回前会调用这里。每个 `app` 登记了必须出现的配置段和串口名。没登记的应用不做业务段校验，已经出现的 `serial` / `relay` / `keywords` 仍然会校验。所以写错字段会在启动时暴露，而不是跑到一半。

### `src/ppx_testkit/logger.py`

`setup_logging(工位名, 日志配置)` 创建 `logs/<工位>/<时间>/`。同一进程里再调用一次会直接返回已有上下文，不会再开一个目录。目录创建失败时改写到系统临时目录。`get_raw_logger("device")` 写入 `device_raw.log`。进程退出前 `cli.main` 的 `finally` 会调用 `shutdown_logging()`。

### `src/ppx_testkit/utils/paths.py`

`project_root()` 用来找 `config/` 和 `resources/`。顺序是：环境变量 `PPX_TESTKIT_ROOT`，PyInstaller 解压目录，再从本文件向上找同时有 `config/` 和 `pyproject.toml` 的目录，最后才是当前工作目录。所以要在项目根目录执行命令，或者设置 `PPX_TESTKIT_ROOT`。

### `src/ppx_testkit/core/factory.py`

应用和硬件之间的接口。常用函数：

- `open_serial(settings, "relay")`：读 `serial.relay`，按 `match` 找口并打开
- `relay_from_settings(settings, transport)`：读 `relay` 段，建成继电器驱动
- `keyword_evaluator(settings)`：读 `keywords` 段

应用文件里不应出现 `import serial`。全仓库只有 `core/serial/` 直接使用 pyserial。

### `src/ppx_testkit/core/runner/stress_runner.py`

压测循环的骨架。应用实现三个方法后交给它：

- `setup`：打开串口、做预检。这里失败就不会进入循环
- `run_cycle(index)`：跑第 index 轮（从 1 开始），返回成败。要停掉整个测试时抛 `TestAbort`
- `teardown`：关串口、按结果决定是否断电。中断和异常之后仍会调用

`StressRunner.run()` 负责计数、连续失败熔断、Ctrl+C，并把 `summary.json` 写到当前日志目录。

### `src/ppx_testkit/exceptions.py`

所有工具异常的根是 `ToolError`。配置问题用 `ConfigError`。串口问题用 `SerialOpenError`、`SerialTimeoutError`、`SerialDisconnectedError`、`PortNotFoundError`。继电器用 `RelayError`。协议和 DLL 用 `ProtocolError` 及其子类。主动停止测试用 `TestAbort`，可以带 `keep_power=True` 表示不要断电。

### `scripts/run_station.bat`

必须用系统 ANSI 代码页能读的英文写，所以文件里没有中文注释。无参数：列出工位并暂停。有参数：`python -m ppx_testkit run <参数>`，标准输出和错误都追加到 `logs\console_<工位>_<时间>.log`，结束时用中文之外的 `[result]` 行标出 PASS / FAIL / 配置错误 / 硬件错误 / 中断。

### `scripts/setup_env.bat`

创建 `.venv`，执行 `pip install -e ".[win,gui,report,dev]"`，并在缺少时复制 `local.yaml`。装完后要自己改串口。

### `config/local.yaml.example`

每个工位一小节，键是 `serial.<名字>.match.port`。名字必须和工位 yaml 里的 `serial` 键一致，例如开关机是 `relay` 和 `device`，舵机是 `servo` 和 `device`，灯板是 `lcb`，R3 刹车是 `tested` 和 `load`。复制成 `config/local.yaml` 后再改。`local.yaml` 已被 git 忽略。

## 9. 想改行为时改哪里

| 想改的东西 | 改这里 |
| --- | --- |
| 本机 COM 口 | `config/local.yaml` 或命令行 `--port 名字=COMx` |
| 循环次数、等待秒数 | 工位 yaml 的 `test` / `stress` / `lamp`，或 `--set` |
| 成功/失败关键字 | 工位 yaml 的 `keywords` |
| 继电器吸合/断开字节 | 工位 yaml 的 `relay`，或 `_fragments/relay_cmd_50_4f.yaml` |
| 转向灯、前灯的亮灭顺序 | `config/stations/turn_signal.yaml`、`headlight.yaml` 里的 `lamp.variants` |
| 组装点击坐标、输入的 SN | `config/stations/_fragments/w3_pctool_clicks.yaml` |
| 日志放哪、控制台打到哪一级 | `config/default.yaml` 的 `logging`，或 `local.yaml` |
| 换一套测试步骤 | 改对应 `apps/...py` 的 `run`，并保持 `run(settings, ctx)` 这个入口 |

改完配置先 `ppx-test show <工位>`。配置错误会直接打印原因，不会去动继电器。

## 10. 开发时怎么确认没改坏

不接硬件：

```bash
ruff check src tests
python -m pytest
```

默认会跳过标记了 `hardware` 的用例。接上设备后才跑：

```bash
python -m pytest -m hardware
```
